# 深空推进器联锁规程 · 不可满足证明审查台

互斥阀位、点火许可与故障隔离约束在联锁规程上线前被编译为布尔约束（受限 DIMACS CNF）。
审查员在此粘贴供应商提交的 DRAT 加/删子句记录，系统以**随步骤变化的活动子句集**为依据逐步复核，
给出不可满足裁决，或首个失败步骤与当时有效约束摘要 —— 绝不只接受“无解”结论。

## 复核规则

- **输入合法性（合并定位，发现即清除旧结论）**
  - 变量须为正整数文字，子句以 `0` 结束；
  - 空子句仅可作为最终矛盾（证明最后一步的新增）；
  - 重复文字、互补文字、越界、截断、无目标删除等全部问题一次性合并定位（来源 + 行号 + 类别）。
- **逐步复核**
  - 新增仅可经当前活动集上的 **RUP** 单位传播、或以首文字为指定枢轴的 **RAT** 成立；
  - 成功步骤展示规则、冲突子句编号链（RUP），或全部反向文字子句的核对结果（RAT，含空悬情形）；
  - 删除立即影响后续推导依据，已删除子句不得继续使用；
  - 仅当活动集导出空子句，方可裁决**不可满足（UNSAT）**。

## 输入格式

```
c 注释
p cnf <变量数> <子句数>     # 受限 DIMACS：头部必需
1 2 0
-1 2 0
-2 0
```

DRAT 记录每行一条、按序执行：`文字… 0` 为新增，`d 文字… 0` 为删除；末步可为空子句 `0`。

## 本地运行

```bash
npm test          # 代码测试（复核核心 + HTTP 层）
npm run build     # 生产构建 → dist/
npm start         # 启动站点 http://localhost:8080（健康路径 /health）
npm run verify    # 一次性验收：测试 + 构建 + 自动拉起服务的 HTTP 冒烟
```

## Docker / Compose

```bash
docker compose up --build web                                # 启动站点（:8080）
docker compose up --build --exit-code-from verify verify     # 一次性验收服务，退出码即结论
```

`verify` 服务依次完成代码测试、生产构建，以及对 `web` 服务的 HTTP 冒烟
（RUP 冲突链、无反向文字子句的 RAT、删除后空子句失败、混合非法输入四个场景），随后自行退出并以退出码报告结果。

## API

| 路由 | 说明 |
| --- | --- |
| `GET /health` | 健康路径 |
| `POST /api/verify` | 请求体 `{cnf, drat}`，返回逐步复核结果 |
| `GET /api/examples` | 四个验收场景的示例输入 |

较长回放由服务端异步响应、前端分批渲染（每批 200 步），页面保持可操作；草稿自动持久化，可一键清空。
